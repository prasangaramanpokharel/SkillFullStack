# RFC 9457 Problem Details for HTTP APIs

RFC 9457 (superseding RFC 7807) specifies a standardized format for carrying machine-readable error details in HTTP response payloads.

---

## 1. Standard MIME Type & Core Members

- **Content-Type**: `application/problem+json`

### Standard Members
1. **`type`** (URI reference): A URI that identifies the problem type. When dereferenced, it should provide human-readable documentation for the problem.
2. **`title`** (string): A short, human-readable summary of the problem type (should not change from occurrence to occurrence).
3. **`status`** (integer): The HTTP status code generated by the origin server.
4. **`detail`** (string): A human-readable explanation specific to this occurrence of the problem.
5. **`instance`** (URI reference): A URI reference that identifies the specific occurrence of the problem.

---

## 2. Extension Members
APIs may extend the problem object with contextual debugging fields:
- `invalidParams`: Array of field validation errors (`name`, `reason`).
- `traceId`: OpenTelemetry / W3C Trace Context identifier.
- `timestamp`: ISO 8601 UTC timestamp.
